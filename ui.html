MDM MCP

MDM MCP Server

A Model Context Protocol (MCP) server that exposes Informatica MDM Business 360 as tools for AI assistants — Databricks Genie, Claude Code, and any other MCP-compatible client. Operators configure which entity types, relationship types, and create permissions are available; the AI can then search, read, and write MDM records through natural-language conversations without direct API access.

Available Tools
search_mdm_entity
Full-text search across MDM records for a given entity type. Returns matched records with relevance scores.
Requires config: Entity Types
list_entity_types
Lists all configured entity type aliases and their underlying MDM entity type strings. The AI calls this to discover what entity types are available.
Requires config: none
get_mdm_entity
Fetches the full record for a specific MDM entity by business entity name and business ID. Returns all fields including metadata.
Requires config: none
get_mdm_relationships
Returns records related to a given entity via a configured relationship type — e.g. all members of a household linked to a person record.
Requires config: Entity Types Relationship Types
list_relationship_types
Lists all configured query relationship types grouped by entity alias. The AI calls this to know which relationships can be queried.
Requires config: none
create_mdm_relationship
Creates a new relationship link between two MDM records — e.g. adding a person to a household. Only allowed combos (from entity → rel type → to entity) are permitted.
Requires config: Entity Types Create Relationship Types
list_create_relationship_types
Lists all relationship types that are permitted for creation, grouped by from-entity alias. The AI calls this before creating a relationship.
Requires config: none
create_mdm_entity
Creates a new master record in MDM. The AI first calls list_entity_create_fields to learn which fields are required, prompts the user for any missing ones, then submits the create request. Returns the new businessId and a view URL.
Requires config: Entity Types Entity Create Fields
list_entity_create_fields
Returns the field definitions configured for creating a given entity type — field label, MDM field name, and whether the field is required. The AI always calls this before create_mdm_entity.
Requires config: Entity Create Fields
Configuration Sections

IDMC Credentials

Username, password, MDM Base URL, and Login Host for your Informatica IDMC org. These authenticate every request the server makes to MDM.
Used by: all tools (session auth)

Deployment

GCP project ID, region, and Cloud Run service name. Controls where the server is deployed. Not passed to the running container.
Used by: gcloud deploy command only

OAuth (Databricks)

Client ID and secret used for OAuth M2M authentication between Databricks (or Claude Code) and this MCP server. The server derives a static bearer token from the secret.
Used by: MCP transport auth — all tools

Create Rel Source System

The MDM source system identifier passed as a query parameter when creating relationships or entities (e.g. c360.default.system). Identifies the origin of created records.
Used by: create_mdm_relationship, create_mdm_entity

Entity Types

Maps short aliases (e.g. person, guest) to MDM entity type strings (e.g. c360.person). Aliases are what the AI and users reference in conversations.
Used by: search, get, create entity & relationship tools

Entity Create Fields

Per-entity list of fields the AI should gather before creating a record. Each row defines a human-readable label, the exact MDM field name, and whether the field is required.
Used by: list_entity_create_fields, create_mdm_entity

Relationship Types

Maps entity alias + relationship alias → MDM relationship string for querying relationships. Controls which entity/relationship combos the AI can read.
Used by: get_mdm_relationships, list_relationship_types

Create Relationship Types

Maps from-entity alias + relationship alias → MDM relationship string + to-entity alias for creating relationships. Separate from query types so create permissions can be restricted independently.
Used by: create_mdm_relationship, list_create_relationship_types
How It All Fits Together
1

Authenticate — on first tool call the server logs in to IDMC using your credentials and caches the session. On 401 it automatically re-logs in.

2

Resolve aliases — the AI passes short aliases like person. The server looks them up in Entity Types to get the MDM entity string (e.g. c360.person) before hitting the API.

3

Guard creates — create operations are only allowed for combos explicitly listed in Entity Create Fields (for entity creation) or Create Relationship Types (for relationship creation). Anything else returns a warning, never an API call.

4

Field gathering — before calling create_mdm_entity the AI always calls list_entity_create_fields first, then prompts the user for any required fields that were not already provided in the conversation.

5

Deploy — the Configurator page writes all settings into env.yaml and runs gcloud run deploy. The running Cloud Run service reads config from environment variables at startup.
